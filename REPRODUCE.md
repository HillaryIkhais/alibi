# Reproduce Alibi from a clean clone

Every number quoted in the README is regenerated by one of the commands below. If a command does not
produce the stated output, the claim is false — trust the command, not the prose.

## Requirements
- Node.js 18+ (BigInt, `node:` built-ins)
- Docker + Docker Compose (only for the optional live regtest lab)

## 1. Policy conformance — 16/16 (no credentials, no Docker)

```bash
node engine/bin/adversarial-test.js
```

```

VENDOR POLICY ENFORCEMENT: VERIFIED (production code)
```

## 7. Live node-backed verifier — 25/25 (regtest)

**Current state:** `evidence/bundle.json` is committed with `summary {passed: 18, failed: 0}`, exit 0,
from a live three-node regtest cycle. It is regenerable with the steps below. Credentials are extracted
to a temp dir outside the repo and are never committed.

### 7a. Stand up the lab from clean volumes

```bash
cd harbor
docker compose down -v && docker compose up -d
# wait for bitcoind to be healthy, then:
bash ./lab/setup.sh
cd ..
```

`setup.sh` creates the bitcoind wallet (Bitcoin Core 32+ no longer auto-creates one), mines 101 blocks
to exit initial block download, funds all three LND wallets, opens Alice↔Bob and Bob↔Carol channels,
and seeds outbound liquidity with two invoice payments so the buyer can route through Bob.

### 7b. Execute one full settlement cycle through the PRODUCTION service — 16/16

The authoritative cycle driver is `engine/bin/production-flow.js`. It calls the real
`CommissionService` (hold invoice creation, `payCommission`, `settleSale`, `reconcile` code paths),
not a duplicated policy class, and asserts the central invariant: settlement is refused before the
outgoing commission payment is verified on the vendor node.

```bash
# Credentials live in a temp dir outside the repo; never commit them.
HARBOR_LND_REST_URL=https://127.0.0.1:10039 \
HARBOR_LND_MACAROON=<alice-admin-macaroon-hex> \
HARBOR_LND_TLS_CERT=<alice-tls-cert-path> \
HARBOR_MARKETPLACE_PUBKEY=<bob-identity-pubkey> \
HARBOR_COMMISSION_PAYEE_PUBKEY=<bob-identity-pubkey> \
  node engine/bin/production-flow.js
```

Expected: `RESULT: 16/16 production stages passed`, exit 0. It writes
`evidence/production-flow.json` (no preimage or credentials) containing the authoritative
`payment_hash`, the negative premature-settle assertion, the verified outgoing-payment result, and
final node states. Use that hash as `ALIBI_PAYMENT_HASH` in §7c.

If channel liquidity has drifted after repeated runs, re-seed both channels with small payments before
running (Bob→Carol and Alice→Bob), and mine a block if `synced_to_chain` is false (see §7c).

Manual equivalent (for diagnosis only, not the proof artifact): generate `PREIMAGE` (32 random bytes)
and `HASH = SHA256(PREIMAGE)`, then with `lncli` on each node's RPC port (Alice `10029`, Bob `10030`,
Carol `10031`): Bob `addholdinvoice --amt 5000 $HASH` → commission BOLT11; call the production handler
`make_commission_invoice` → sale BOLT11; Carol `payinvoice --pay_req=<sale> --force` → HTLC held at
Alice (`ACCEPTED`); call production `payCommission` in the background; Bob `settleinvoice $PREIMAGE`;
then production `settleSale` verifies node state before releasing the buyer.

### 7c. Run the independent verifier

Extract each node's `readonly.macaroon` (hex) and `tls.cert` from its container. Because each LND node
has its own self-signed cert, concatenate all three certs into one CA bundle and pin that path:

```bash
ALIBI_ALICE_REST=https://127.0.0.1:10039 ALIBI_ALICE_MACAROON=<alice-hex> \
ALIBI_BOB_REST=https://127.0.0.1:10040   ALIBI_BOB_MACAROON=<bob-hex> \
ALIBI_CAROL_REST=https://127.0.0.1:10041 ALIBI_CAROL_MACAROON=<carol-hex> \
ALIBI_TLS_CERT=<path-to-concatenated-certs> ALIBI_PAYMENT_HASH=<64-hex> \
  node engine/bin/verifier.js > evidence/bundle.json
```

Regtest keepalive: if nodes report `synced_to_chain: false` while their `block_height` already matches
bitcoind and channels are active, LND's sync flag has gone stale. Mine one block
(`generatetoaddress 1`) and wait ~8s; all three flip back to `true`. The verifier correctly fails
closed on `node.synced` in that state — do not bypass it.

The verifier fails closed: exit 2 on missing credentials, exit 1 on any failed check, exit 0 only
when all 18 pass. The preimage is SHA-256-checked in memory and redacted before the bundle is written.
No macaroon, cert, or preimage is included in the committed artifact.

## Credential hygiene
Credentials are never committed. `.gitignore` blocks `*.macaroon`, `*.seed`, `*.key`, `*.cert`,
`data/*.pass`, and `*.log`. `evidence/` is intentionally committed so proof artifacts are visible.
See `evidence/runs/2026-11-17-offline/credential-scan.txt` for the history-wide scan.
